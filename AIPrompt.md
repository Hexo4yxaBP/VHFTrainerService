# Промпт для проектирования архитектуры и реализации сервиса тренировки навыков морского VHF-оператора

Ты - опытный архитектор программного обеспечения и разработчик с глубокими знаниями в области backend-разработки на языке Go, интеграции с Telegram API для создания ботов, распознавания речи, генерации аудио, симуляции радиопомех и протоколов морской радиосвязи (VHF и GMDSS). Твоя задача - спроектировать архитектуру и план реализации сервиса для тренировки навыков морского VHF-оператора. Сервис должен быть реализован в виде Telegram-бота на языке Go, с использованием подходящих библиотек и внешних API (например, для распознавания речи - Google Cloud Speech-to-Text или аналогичные; для TTS - Google Text-to-Speech или gTTS; для симуляции помех - аудио-библиотеки вроде go-audio или FFmpeg через Go).

## Требования к сервису

1. **Распознавание речи пользователя в текст**: Бот должен принимать голосовые сообщения от пользователя в Telegram, конвертировать их в текст с учетом морского жаргона и протокола VHF (например, распознавать фразы вроде "Mayday Mayday Mayday" или позывные судов). Обработать возможные ошибки распознавания и подтвердить у пользователя.
2. **Ответ на запросы по протоколу морской радиосвязи**: На основе распознанного текста генерировать ответы в соответствии с стандартами VHF (ITU-R M.493-15 для DSC, или общий радиопротокол). Ответы должны быть вежливыми, структурированными (позывной, сообщение, подтверждение) и учитывать сценарии: рутинные вызовы, бедствие, безопасность, срочность.
3. **Конвертация текста в аудио с радиопомехами**: Преобразовать текстовые ответы в аудиофайлы с добавлением эффектов радиопомех (шум, искажения, эхо, как в реальной VHF-связи). Использовать библиотеки для аудиообработки в Go (например, go-audio, beep или интеграцию с FFmpeg). Аудио отправлять пользователю как голосовое сообщение в Telegram.
4. **Генерация случайных событий в море**: Сервис должен симулировать случайные морские события (например, шторм, столкновение, человек за бортом, запрос помощи) и генерировать сообщения о них в формате VHF-радио. Перечень событий должен быть настраиваемым (через конфигурационный файл или админ-панель в боте). События генерируются случайно по таймеру или по запросу, с вариациями (регион, тип судна, детали).
5. **Передача сообщений GMDSS по расписанию**: Для выбранного региона (например, Балтийское море, Атлантика) бот должен отправлять симулированные GMDSS-сообщения (NAVTEX, DSC, MSI) по расписанию (например, каждые 30 минут). Использовать реальные шаблоны GMDSS, но в тренировочном режиме. Пользователь выбирает регион в настройках бота.

## Архитектура

- **Микросервисная или монолитная структура**: Предпочтительно монолит для простоты, но с модулями (handlers для Telegram, speech recognition, TTS, event generator, scheduler).
- **Компоненты**:
  - Telegram Bot API: Используй библиотеку tgbotapi или go-telegram-bot-api для обработки сообщений.
  - База данных: PostgreSQL или SQLite для хранения пользовательских сессий, настроек (регион, список событий), логов.
  - Асинхронная обработка: Используй goroutines для параллельной обработки распознавания, генерации аудио и событий.
  - Интеграции: API для STT/TTS (с ключами в env), scheduler (cron в Go для GMDSS).
  - Безопасность: Обработка токенов, rate-limiting, логирование ошибок.
  - Масштабируемость: Учитывай возможность развертывания на Heroku, AWS или VPS.
- **Диаграммы**: Опиши архитектуру с помощью текстовых диаграмм (UML-like или блок-схемы в Markdown).

## План реализации

- **Шаги разработки**:
  1. Настройка проекта: Инициализация Go-модуля, установка зависимостей.
  2. Бот-скелет: Обработчики для /start, /help, голосовых сообщений.
  3. Модуль распознавания речи: Скачивание аудио из Telegram, вызов STT API, парсинг текста.
  4. Логика VHF-протокола: FSM (finite state machine) для диалогов (состояния: ожидание вызова, обработка, ответ).
  5. Генерация аудио с помехами: TTS -> добавление эффектов -> отправка.
  6. Генератор событий: Конфиг в JSON/YAML, случайный выбор, интеграция в чат.
  7. Scheduler для GMDSS: Библиотека gocron, шаблоны сообщений по регионам.
  8. Тестирование: Unit-тесты, интеграционные тесты, симуляция сценариев.
  9. Деплой: Dockerfile, CI/CD с GitHub Actions.
- **Потенциальные вызовы и решения**: Обработка ошибок STT (повторный запрос), лимиты API, производительность аудиообработки.
- **Оптимизации**: Кэширование аудио, мультиязычность (английский + русский для морского жаргона).

## Кодовые примеры

Вот фрагменты кода на Go для ключевых частей:

### Пример обработки голосового сообщения (Telegram Handler)

```go
package main

import (
    "log"
    "github.com/go-telegram-bot-api/telegram-bot-api"
)

func main() {
    bot, err := tgbotapi.NewBotAPI("YOUR_BOT_TOKEN")
    if err != nil {
        log.Panic(err)
    }

    u := tgbotapi.NewUpdate(0)
    u.Timeout = 60

    updates := bot.GetUpdatesChan(u)

    for update := range updates {
        if update.Message == nil {
            continue
        }

        if update.Message.Voice != nil {
            // Скачиваем голосовое сообщение
            fileID := update.Message.Voice.FileID
            file, err := bot.GetFile(tgbotapi.FileConfig{FileID: fileID})
            if err != nil {
                log.Println(err)
                continue
            }
            // Далее: вызов STT API для конвертации в текст
            text := speechToText(file.FilePath) // Функция STT
            // Обработка текста по VHF протоколу
            response := processVHF(text)
            // Генерация аудио с помехами
            audioFile := textToAudioWithNoise(response)
            // Отправка аудио
            msg := tgbotapi.NewVoice(update.Message.Chat.ID, tgbotapi.FilePath(audioFile))
            bot.Send(msg)
        }
    }
}
```
